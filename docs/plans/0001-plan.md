This plan replaces direction-based grouped interfaces with terse one-way boundary contracts. It also removes ambient interface values and repeated identity bindings.

The phases are checkpoints inside one implementation. They are not versions or separate deliveries.

---

## 1. Objective

Make each interface one compact declaration of one complete schema instance crossing the active document boundary.

The final dataflow is:

```text
outside instance
  -> RECEIVES interface
  -> source-backed trigger
  -> process-local bindings
  -> process
  -> EMITS interface
  -> outside instance
```

## 2. Accepted contract

### Interface surface

```oak
<interfaces>
review-request RECEIVES schema.amendment-review-request
review-result EMITS schema.amendment-review: "Returned only to the successor coordinator."
</interfaces>
```

- `RECEIVES` and `EMITS` are the complete closed interface flow set.
- One interface entry occupies one line.
- Consecutive entries use one LF with no blank separator.
- The interface id appears once inside the interfaces part.
- References from other parts remain qualified as `interface.<id>`.
- The schema target can be local or relative.
- Text after `: ` is one optional JSON string.
- A description adds boundary meaning absent from the id and schema.
- `in`, `out`, and `inout` no longer exist.
- A duplex relationship uses two interfaces.

### Trigger handoff

```oak
<triggers>
trigger.amendment-review-requested.event := "An amendment review is requested."
trigger.amendment-review-requested.source := interface.review-request
trigger.amendment-review-requested.process := process.review-amendment
</triggers>
```

- A source must target one local `RECEIVES` interface.
- A source-backed trigger has no seeds.
- Its selected process must declare an input schema.
- The receive interface schema and process input schema must resolve to the same schema entry.
- The received instance becomes the complete process input.
- Event-only triggers retain explicit seeds from literals, constants, and state.
- Trigger events remain required semantic signposts.

### Process values and emission

```oak
<processes>
<process id="review-amendment" name="Review amendment" input="schema.amendment-review-request" output="schema.amendment-review">
ACT output="schema.amendment-review": Review <AMENDMENT> and produce <DECISION>. (AMENDMENT=$AMENDMENT) -> DECISION
EMIT interface.review-result
</process>
</processes>
```

- Process values are limited to literal, constant, state, and binding.
- `$interface.<id>.<placeholder>` no longer exists.
- `EMIT interface.result` fills the target schema from same-named visible bindings.
- `EMIT interface.result (RESULT=$FINAL_RESULT)` remains available for explicit projection.
- An explicit emit binding set must be non-empty and equal the interface schema placeholders.
- `EMIT interface.result ()` is invalid.

### Arrival API

```python
Arrival(
    interface="interface.review-request",
    values={"AMENDMENT": "..."},
)
```

- One arrival contains exactly one event or one local receive interface.
- An event arrival carries no values.
- A receive arrival carries one complete value mapping for its interface.
- The old `source` plus arbitrary `interfaces` mapping is removed.

### Generated interpretation instructions

Generate each applicable line once, in this order:

```text
RECEIVES accepts one complete instance of its schema.
A source-backed trigger supplies the received instance as the selected process input.
EMITS publishes one complete instance of its schema.
EMIT without bindings fills the target schema from same-named visible process bindings.
Text after `: ` states boundary meaning absent from the interface schema.
```

- Select each line from actual node features.
- Do not repeat interface ids, schemas, or descriptions in the instructions.
- Omit the description line when no interface has a description.
- Remove the old generic interface direction instruction.
